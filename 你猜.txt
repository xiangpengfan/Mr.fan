ps（关于哈希算法和字典内容不可变的原因）：
哈希算法是一个无限大的网，给世界上所有的数据（词，词组，数字等）固定了一个位置，哈希位置和数据一一对应。
假如变量可以存为key，那么变量一旦改变他的哈希位置（通过哈希算法得到的位置）也会随之该改变，用户查找数据时就会找到后面哈希位置的那个数据，原来的哈希位置的数据没找到
所以变量不可存入字典

如果内容跟着key值走，那就必须时刻监视key值的变化，内容就会变得无比冗杂

1.接受另一个函数作为参数；

filter(function,iterable): 从序列中筛选出符合条件的元素
函数里的 return 相当于判断条件，符合条件的保留，不符合的过滤掉

filter 执行时，会自动把序列里的每个元素依次传给判断函数。
如果筛选条件不是固定写死的，需要自己额外传参数来控制，单层函数就不够用了，这时候就要用闭包。
例子：比如要筛选不能被 n 整除的数，n 每次都不一样，就需要用闭包。
实现方式：给参数函数外层嵌套一个函数，用于接收额外参数
def _not_divisible(n):
    def check(x):
        return x % n > 0
    return check
外层函数负责接收额外参数，内层函数负责真正判断，这种结构就是闭包。
闭包定义：函数内部嵌套函数，内层函数使用了外层函数的变量，且外层函数返回内层函数对象。
调用时，额外参数先传入外层函数：
it = filter(function(n), it)

def count():

             return i*i
        fs.append(f)    #这里调用了三次，我们必须用三个变量来接收
    return fs

装饰器核心笔记
装饰器：函数套函数，闭包的具体体现
1. func.__name__
作用：获取函数名称；函数被装饰后，默认会显示包装函数名wrapper
2. 包装函数
就是闭包的内层函数，用来给被包装的函数添加额外功能

3. 基础装饰器写法
def log(func):
    def wrapper(*args, **kw):
        return func(*args, **kw)
    return wrapper
4. @log的用法
等价于 now = log(now)
调用顺序：从外到里，先执行包装逻辑，再执行原函数
原函数的参数，用*args, **kw统一接收
5. 带参数的装饰器
装饰器自身需要传参时，再额外套一层函数
6. 保留原函数名
在wrapper上方加 @functools.wraps(func)
让__name__显示原函数名，而非wrapper

函数只要被调用就会自动执行，无论是赋值，直接写，丢在表达式里，但函数的return值不会返回，所以return是函数的核心
def text（）：
	print（‘赋值也会执行’）
a=text（）：这样赋值也会执行text函数

对于带装饰器的函数，装饰器通常是两层结构，函数带括号f（），是调用两层结构，而函数本身单独调用  像这样 f，只是调用了一层结构，他会停在第一层的返回上面，也就是返回一个函数！
比如：装饰器
def log（funct）：
	def wrapper（）：
		print（‘1’）

return wrapper

@log
def f（）：

偏函数partial

itertools.takewhile(partial(first_n_minus_1_items, N=N), odd_numbers)
partial(first_n_minus_1_items, N=N)的位置只允许输入一个参数而first_n_minus_1_items需要两个参数，因此我们需要先用partial把一个参数输进去
也就是对函数先进行一部加工使它的参数满足高阶函数的要求

面向对象父类子类核心笔记
 
父类和子类
- 父类也称作基类、超类，是更通用、抽象的类。
- 父类特点：适用范围广，当不确定后续会有哪些子类使用功能时，将父类作为参数传入，兼容性更强。
- 子类特点：继承父类的全部方法，能减少重复代码；同时拥有更多专属方法，功能更丰富、逻辑更具体。现实中动物需要细分，不能将所有有进食、排泄行为的生物统称为动物，细分出的猫、狗、乌龟等就是子类；实际业务落地，也需要依靠子类实现具体逻辑，子类新增专属方法不会对原有父类产生任何影响。
 
继承
子类可以直接调用和使用父类已有的方法，实现代码复用。
 
多态
以父类作为参数的函数，也可以传入该父类的子类对象。
凡是以父类作为参数的函数，都能兼容其子类作为参数。一旦业务中的父类确定，后续所有具体业务，都可以基于该父类开发子类，无需改动原有代码，大幅减少开发工作量。
 
鸭子类型（Python特有）
对于需要传入父类F作为参数的函数，父类F的子类自然可以作为参数传入。
Python对参数类型的限制更宽松：如果一个类并非F的子类，但它具备F的核心功能（比如读写、访问、上下文管理等），函数也允许它作为参数使用，也就是说具备相同核心能力即可通用，并非一定要有继承关系。

isinstance（待判断对象，数据类型）#他的返回值只有true和Flase，当我们用type()判断出一个函数的类A时，如果发现它还属于另一个类B，那么B就是A的父类，同样，我们用父类B创建一个对象，仍用isinstance（）判断，发现它还属于类C，那么C就是B的父类，也是A的爷爷类

getattr（对象，方法名称/变量名称）#获得一个类的方法或者变量
delattr（对象，方法名称/变量名称）#删除一个类中的方法或者变量

实例属性：self中的变量，储存在类本身，不用函数看不到

ps：如果把类比作一个人的话，实例对象和类对象加一起构成了这个人的所有钱，实例对象就像私人小金库，平时看不见但里面存的有钱，类对象就像是用来明面上花销的钱，比如吃饭喝水买生活用品之类的
--------------------------------------------------------------
实例属性属于各个实例所有，互不干扰；
类属性属于类所有，所有实例共享一个属性；
当实例属性和类属性名称相同的时候，系统会优先调用实例属性，类属性就被隐藏了，所以不要对实例属性和类属性使用相同的名字，否则有些时候将产生难以发现的错误。


****类属性通过类名调用，实例属性通过self调用************
举例：
class Student(object):
...     count=0
...     def __init__(self,name):
...         self.name=name
...         Student.count+=1
name是实例属性，通过self调用，而count是类属性，通过Student调用。

property用法：装饰方法，property 可以把类里的方法的返回的封装变量变成普通属性一样调用，既保护了封装变量，又让读写更简洁。
一、什么时候用property？
类里有变量不想被外部直接乱改：先做封装（__变量）

二、基本逻辑
把私有变量封装起来
用 @property 把方法伪装成普通属性, 外部可以用 对象.属性 访问，不再需要写 对象.get_xxx()
三、只读用法（getter）
class std（object）：
	@property
	def 函数名（self）：
		return self.__num
作用：让外部只能读，不能直接改封装变量。
四、可读写用法（getter + setter）
class std(object):
	@property
	def 函数名(self):
		return self._num
	
	@函数名.setter
	def 函数名(self,num):
		self.__num=num     #setter里面必须是设置方法,否则逻辑会混乱
作用：既可以读，又可以安全地修改，并能加校验。
五、重要规则
@property 本身是 getter
setter 内部必须是赋值操作，否则逻辑混乱
一个 property 只对应一个对外属性

错误处理
一个函数调用了另一个函数，那么调用的函数被称为主调函数，被调用的函数称之为被调函数
关于try
结构
try：#把需要检测错误的代码放入这里，出错误后立即跳转至except，后续代码不再执行
以下：
print（‘我是第一行’）；a=10/0；print（‘我是第三行’）               #第二行出错误第三行不再执行
except 错误类型 as e：    #except可以写很多个，每个只能检测一个错误类型，异常也是类，由于子类本身也属于父类的一种，代码会从上往下执行匹配。一旦匹配到父类入口，流程即被接管，排在后面的子类捕获逻辑将被直接屏蔽。
else   #和try绑定，当try可以完全执行时else会紧接着执行
finally   #无论有没有错误，它都会执行，写了就会执行
关于调用栈
上游函数：被其他函数调用的函数（相当于水流的源头）
下游函数：主动调用其他函数的函数（相当于水流的下游）
调用深度：函数距离程序入口函数的层级距离，即为该函数的深度。
报错传播规律：若深度为 5 的函数发生错误，它上方的 5 层调用函数都会依次报错。

1. PDB 是什么？
一个慢动作播放器。
能让你一行一行跑代码，随时偷看每个变量当前是什么值。
优点：理论上，只要时间够，可以看到程序运行的所有细节，再隐蔽的 bug 也能揪出来。
缺点：太费时间，平时一般不这么用，只有遇到疑难杂症才上。
2. pdb.set_trace() 是什么？
PDB 的一个快进键。
用法：在你觉得前面的代码肯定没问题的地方，插一行 pdb.set_trace()。
效果：程序会全速跑到这一行，然后自动暂停，进入慢动作模式等你调试。
结论：比纯 PDB 快一点（省去了从第一行开始按的时间），但跟不用调试器相比，还是很慢。

文档测试

代码示例能比自然语言更精确地传达复杂逻辑，降低理解门槛。而用户如果能直接运行这些示例并成功，就相当于为框架或模块提供了一个实时的可用性验证——示例能跑通，说明当前的电脑环境与文档描述一致；跑不通，则可能意味着模块接口已变更或文档已过时，不能再用了。
验证的目的是为了确保我们所使用的工具是对的，不然等我们写完再确认就晚了

doctest模块
自动运行 ** 文档字符串（''' '''）** 里的测试代码，验证模块是否能正常使用、结果是否，正确使用方法如下

class 自定义类名:
    '''
    这里写文档说明 + 测试代码
    >>> 测试语句1
    预期结果1
    >>> 测试语句2
    预期结果2
    '''
    def 方法(self):
        pass

if __name__ == '__main__':                  # ⚠️ 必须顶格写，不能缩进！
    import doctest
    doctest.testmod(verbose=True)       # verbose=True 显示详细测试结果

如此，启动文档代码就会实例代码就会自动运行


doctest 会逐字严格核对示例代码的实际输出与预期结果是否一致，因此预期结果需遵循以下规则：
正常运行结果必须与代码实际运行输出一字不差完全一致（空格、引号、换行、字符均不可出错）。
异常报错结果（唯一例外）若预期结果为异常报错信息，无需完整抄写冗长堆栈，可使用 ... 省略中间内容，仅保留首尾关键异常信息即可。
例如
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
ZeroDivisionError:  division by zero        #英文冒号加空格
可以写成
raceback (most recent call last):
...
ZeroDivisionError:  division by zero        #英文冒号加空格

实现对应的类 / 函数
在文件最后（顶格写），添加运行代码

计算机存储与I/O基础
内存和磁盘都属于存储设备，二者分工不同：
- 内存：用于运行、操作程序与数据，相当于工作坊
- 磁盘：用于持久保存数据，相当于仓库
I/O 流的作用，就是在不同存储设备之间传输数据。
这里存在一个核心性能矛盾：
CPU/内存的读写速度远高于磁盘。
那么在数据传输时，CPU 空闲出来的性能该如何处理？由此产生两种 I/O 模型：
1. 同步 I/O：CPU 等待 I/O 完成，期间不处理其他任务
2. 异步 I/O：CPU 不必等待，可先去执行其他任务
数据在传输时，也有两种典型方式：
1. 逐字节实时发送
属于低级 I/O，更接近计算机底层操作
2. 先写入缓冲区，攒够一批再批量传输
属于标准 I/O，效率更高、速度更快

环境变量：以键值对的形式储存在操作系统中，可以理解成操作系统贴在系统里的一堆 “便利贴”。系统和程序靠这些便签，快速找到文件路径、运行参数、配置信息，从而正常启动和执行。
注册表：可以理解为硬盘中的环境变量，但是他会储存更多的信息
以下方便理解：
这些 “便利贴” 本质上是数据，运行时会被加载到内存里，以电路高低电平的稳定电压形式保存。
当代码中写下读取某个环境变量的指令时：
解释器或编译器会先把这条高级语言指令，翻译成 CPU 能识别的机器指令，也就是一串 0 和 1；
CPU 对机器码进行译码，解析出 “读取某个环境变量” 的操作；
接着根据变量名，在内存中定位到对应的数据地址，通过控制电路读取该处的电平信号；
这些电压信号会被转换成数字信号，最终以数据形式返回给程序，程序就能拿到环境变量里的内容并使用

写在题记
写入文件和读取文件可以很方便的将数据传输入文本文档，用来传输字符串很方便，但是只能用来传输字符串，如果我们要传输其他类型的数据，如列表，字典，常数，浮点，布尔，与自定义的数据类型等，该怎么办呢，答案是使数据序列化，序列化不仅可以保存数据的类型，还可以保存数据的结构。
序列化，变量从内存中变成可存储或传输的文件的过程
常见的文件类型有两种
二进制文件：将文件序列化为二进制形式，快读快写，追求速度
json文件：将文件序列化为文本形式，结构清晰，打开可读，追求可维护性

同样以写入读取文件起手
write()-------------->.txt-------------->read()
序列化导入导出文件
pickle.dump(文件)/json.dump(文件)------------------->二进制文件或者json文件---------------------->pickle.load(文件)/json.load(文件)
pickle：将文件序列化为二进制形式；json：将文件序列化为json形式

#我们把中间的数据包，即json文件，暂时称之为中间文件
import jsonw
pickle.dump(包含代码的文件)：直接把数据编码存入文件中
pickle.dumps(代码)：把数据编码并显示出来，但不存入文件
pickle.load(包含json数据的文件)：对不在程序中的文件解码并输出结果
pickle.loads(json数据)：对已经接收到了二进制或者json数据，进行解码
总结：带's'的只在程序内运行并显示，称之为内存中解码或者编码，不带's'的要与文件进行交互，内存中解码或者编码数据多用于网络传输，数据库传输等场景，用在当我们需要直接发送字符串数据而不发送文件，或者我们需要直接接受文件而不是接收字符串的时候

json文件的进阶知识
即使强如json，可以序列化的数据类型也有限，只能序列化dict 字典         list / tuple 列表 / 元组           str 字符串       int / float 数字         True / False 布尔值           None 空值
可以看到，如果是我们自定义的数据类型，它将无法序列化
那我们自定义的数据类型应该如何序列化呢，答案是自定义编码和解码方式
	json.dump(文件，default=编码方式)

关于文本文档的拓展，为什么文本文档只能传输字符串并且不能作为中间文件
因为它使用utf-8编码，会把任意的数据类型变成字符串形式，如果你存入数字1和字符串‘1’，最后存入的结果都是字符串‘1’，这样的话，你把他读取出来不知道它是代表字符串还是数字，会造成语义混乱
另一个原因是它只能解码utf-8编码的文件，无法解码程序语言
另外，如果我们给它加个标识的话，比如，数字1==ss 1          字符串‘1’==zz 1         就可以区别两者了，确实如此
事实上json文件就是这样做的，json本质上就是字符串，只不过它更全面更好

#多线程特有的锁，当多线程操作同一个变量时，可能会导致各个线程操作对象的代码的汇编指令错位，从而引起结果不可预期，为了防止这种情况，当一个变量被多个线程操作时，我们把各线程操作对象的代码的汇编指令打包起来，每次只运行一组，类似于拿一个框，把一组汇编指令框起来，保证每次只允许一个线程操作该对象，我们把这种给变量加上框的方式称之为上锁
多锁的一个特点
#操作对象的代码的汇编指令：
对于同一个变量来说，不同的线程操作变量的代码编译成汇编指令是一样的，最终只有两句：
1.计算等式右边的值
2.把值赋值给等式左边的变量
对于同一个变量balance：
balance=balance+5；     balance=banance-5
x1 = balance + 5              x1 = balance - 5
balance = x1                    balance = x1
两个线程正常的操作代码所生成的汇编指令一旦错位，结果也就不可预测


锁死：如果多个变量每一个都被多个线程操作，我们需要上很多把锁，又出现这样的情况，拥有上锁变量A的线程想要拥有上锁变量B，恰好，拥有上锁变量B的线程想要拥有上锁变量A
lock_A = threading.Lock()
lock_B = threading.Lock()

lock_A.acquire()；lock_B.acquire()
lock_B.acquire()；lock_A.acquire()                     #死锁代码演示

多线程的瓶颈
GIL锁：存在于python解释器中，即使有多核cpu，在同一块内存中，同一时间也只能运行一个线程，多个线程在在同一个进程中只能交替运行，这种单进程中线程交替运行的方式大大减弱了多线程并发的运行速度，同时，由于单个进程只能运行单个线程，所以单进程的最大核能被限制在了单核
注意即使是只能单核运行，相较于循环单线程来说，多线程也有一些单线程无法比拟的优势，以下他们的区别：
如果单个线程任务全部是在计算，即完全是在cpu中运行的话，那两者速度差不多，甚至因为多线程要给变量上锁，会更慢一些
但如果线程运行的任务不只是计算，即中间存在等待cpu闲置期，像等待用户输入，等待数据包传入；多线程的交叉运行可以合理的利用这个空窗期，所以速度大大超越单线程循环


因为GIL锁的存在，python每一个进程最多只能占满一个核的性能，原因如下：
python的每一个进程只能占用一个线程，每一个线程最多占用一个核的性能
python每一个进程只能运行一个线程
python每个进程拥有一个GIL锁，GIL锁规定每一个进程中每一瞬间只能有一个线程运行，如果是纯计算线程任务，所有的瞬间加起来其实也就是一个线程在运行，从进程的视角来讲，GIL锁限制了线程的数量，导致每一个进程最多占用一个核的性能
每一个线程最多占满一个核的性能
只有纯计算没有等待间隔的任务才能把线程性能拉到最满
对于一个纯计算的线程来说，无论它怎么切换，在任何瞬间，这个线程只能也一定能占据1个核心
如果一个cpu有12个核，因为线程任务在某一个瞬间只会在一个核心上，所以一个线程计算无论如何也只能占满一个核的性能
我们取极值来验证这一点
对于任意的运行时间
如果线程任务的所有瞬间都集中在一个核上，很显然占满了一个核的性能
如果线程任务的所有瞬间平均分配在所有核上，很显然占了每个核1/12的性能，一共也是占了一个核的性能

所以只有在io任务较多的情况下我们才用多线程
如果是多io任务，因为有等待间隔，所以单个线程或者循环单个线程无法将cpu占满
这个时候就需要我们采用多线程通过增加io数量来填充等待间隔从而提高cpu利用率

但是在线程中，它只能允许定义的时候输入几个参数，我们没有其它输入的空间，所以我们的一切操作只能在线程的参数函数中进行，参数函数见下：
     t1 = threading.Thread(target=参数函数，name='线程名称')
我们要在线程中把变量传入一个函数中，其实要解决的就两个问题：
1.变量的定义问题，在哪里定义变量                                  #在参数函数中定义
2.变量的传递问题，怎么把变量传递到线程函数中去         #以更高层的容器为媒介  先传入容器再传入到指定的函数

Thread.local()底层就是这么运行的，它底层创建了一个字典容器，在参数函数中定义变量，把变量放入这个字典容器中，在线程函数中通过这个字典容器来获取变量的值
并且，这个字典保存了线程的PID，以保证每个线程都能获取到自己定义的变量值

其实就相当于把函数拓展了类的self功能

以下是正文
线程局部变量Threadlocal：在多层级的函数调用中作为参数中转站，允许你在指定位置提取参数，变量写在全局变量的位置，但实际是给每一个线程都拿到一个属于自己的‘副本’
local_school = threading.local()              #首先你需要创建一个仓库
def process_thread(name):
    local_school.student = name              #仓库在每个线程中都会复制一份，互不相交，保存的是该线程的局部变量
t1 = threading.Thread(target= process_thread, args=('Alice',), name='Thread-A')     #当一个函数拥有threading.local()，同时这个函数又是线程的参数，那么就相当于给这个线程造了一个‘self’，即local_school

多进程/多线程优缺点和使用条件
一、工作模式分类
1. Master-Worker模式：多线程、多进程都属于该模式
2. 对应模式：单线程、单进程工作模式
二、多进程vs多线程
- 多进程：内存相互隔离，稳定性更强
- 多线程：开销更轻、更轻量化，运行速度更快，但共享内存，稳定性较弱
三、单核CPU多任务原理
单核CPU也能实现多任务并发，依靠高频任务切换实现：
CPU按极快速度在不同任务间轮流切换，本质仍是串行执行，但切换速度肉眼无法感知，看起来像同时运行。
⚠️注意：CPU每次任务切换都会消耗资源，任务数量不宜过多，过量反而会降低整体运行效率。
四、任务类型与CPU任务数配置
按CPU执行特征分为两类：
1. 计算密集型任务
特征：CPU全程持续运算，无空闲等待
举例：圆周率计算、视频解码等
配置建议：任务数=CPU核心数最合适
2. IO密集型任务
特征：CPU大量时间在等待网络、文件读写等IO响应
配置建议：可开启足够多任务，充分利用IO等待时间，提升整体并发效率

一些关于通信的问题
一台计算机可以有4个 ip 地址，因为它同属于很多个组织之下;每个组织都会给它分配一个 ip 地址
这四个地址包括：主机地址，内网地址，外网地址，虚拟机地址
主机地址用来自己和自己通信
内网地址：用来在局域网内通信，它由家庭路由器或者家庭交换机分配地址
外网地址：用来访问互联网，它由运营商的中枢交换机分配地址

由于ip4地址有限，为了节约ip4地址的使用，我们采用以下做法
多个具有内网ip的计算机通过一个路由器的公网 IP 访问公网，这个做法叫 NAT（网络地址转换）
由于有NAT的存在，现在的计算机通常只有2-3个ip地址：主机地址，内网地址，虚拟机地址

下面我们来讲一下信息传递的方式
笔记本都是带有天线，一般在屏幕两侧
台式电脑在天线和有线网卡之间二选一，目的都是为了发送电磁波信号
所有的设备电磁波信号传递都是先传给路由器，路由器将电磁波信号经光纤或者信号塔传播至运营商的巨型交换机又称全网总交换机上，然后接入互联网


外网传输数据包时，路由器只能识别到端口信息。将路由器的公网端口，绑定到内网某台电脑指定端口的操作，就叫做端口映射。
端口映射通过把路由器的公网地址输入浏览器，在公网地址网页中设置

租一台frp服务器，将frp服务器的某个端口和服务端计算机某个的端口做一对一的映射，客户端通过访问frp服务器来访问服务端计算机，使服务端计算机可以穿透局域网接受客户端数据的方法叫做内网穿透

不同种类的ip地址只能由对应组织的成员访问，主要是因为客户端的通信问题
主机地址：127.0.0.1               客户端想要访问某个计算机的主机地址时，输入127.0.0.1只能访问客户端自己

公网地址：0.0.0.0                   开启公网ip并做端口映射之后，客户端发送的数据包只需要发送到服务端路由器上就可以直接接收

正则表达式：用来匹配、检索、筛选文本的模板，主要用来筛查格式和提取内容

正则表达式的函数代码
import re
re.match(正则表达式,test)       #主要用来筛查格式，从头到尾的匹配，匹配成功返回Match对象,不成功返回None
re.split(正则表达式,test)          #用来切分字符串，返回一个列表，里面包含切分后的值，以下：
代码：re.split(r'[\s]+','a b  c')
输出：[a,b,c]

原子：代表的是字符串中一个字母占据的一个位置，是位置量化的最小单元
【a b (?:cfd）】：a和b和（cfd）各占了一个单元，‘？：’表示该括号只用来做量化不用来做输出单元
正则表达式由通配符和量词构成，通配符用来表示数据的类型，量词用来表达数据占了多少个原子，如果只有单个通配符而没有量词，那就说明只占一个原子
常见通配符
\d	匹配一个数字	                        等价 [0-9]
\w	匹配一个字母、数字、下划线	等价 [0-9a-zA-Z_]
\s	匹配一个空白字符	                空格、制表符 \t、换行 \n、回车 \r 都算
\D	匹配一个非数字	                和 \d 相反，不是数字都能匹配
\W	匹配一个非单词字符	        和 \w 相反，不含字母、数字、下划线
\S	匹配一个非空白字符	        和 \s 相反，不是空白都能匹配
\.      匹配任意值
超级通配符，字符集：只占一个原子，原则上可以匹配任意的数据，只要能用键盘打出来，以下：
[0-9]:匹配一个数字
[a-zA-Z]:匹配一个字母无论大小写
[0-9a-zA-Z]:匹配一个字母、数字

常见量词
*        任意个字符(含0个)     有无均可数量不限
+        至少一个字符            不能没有最少1个
?        0个或1个字符            可有可无最多1个
{n}      固定恰好n个字符      不多不少正好n个
{n,m}    n到m个字符            最少n个最多m个
{n,}     至少n个字符             最少n个上不封顶

一些特殊的匹配规则
|:A|B用来表示满足A或B任意一个条件即是匹配成功
^:写在正则表达式开头表示从行开头开始匹配，^\d     行开头的第一位应该是一个数字
$:写在正则表达式结尾表示从行结尾开始匹配，$\d    行结尾的最后一位应该是一个数字



以上我们都是以筛选格式来作为匹配目标，只能返回函数本身或者None，下面我们将以抓取数据作为目标
（）：用来表示要提取的分组group，以下：
m = re.match(r'^(\d{3})-(\d{3,8})$', '010-12345') #括号里面的是可以提取的内容
m.group(1)     #提取第一个括号里的内容
’010‘
m.group(2)     #提取第二个括号里的内容
‘12345’
m.group()       #返回整个被匹配的字符串
’010-12345’
我们假设要从很多文本上抓取文件，但是要抓取的文件是一样的，如果我们重复编写很多的正则表达式不仅内容重复，运行效率也会降低
所以我们引入预编写：一次编写多次使用
import re
r= re.compile(正则表达式)  #这里编写多次使用的表达式，可以加括号
g=r.match(test).group()      #这里直接输入文本然后提取内容

正则的一个特性
把单个通配符 + 量词称作一条小匹配规则
正则默认特性：贪婪匹配—— 每条规则优先匹配尽可能多的内容；量词后加 ? 变为非贪婪匹配，以下：
re.match(r'(.+)(\d+)', 'abc123')
’abc12‘，‘3’ 
匹配逻辑：
.+ 贪婪特性，默认尝试匹配最大范围 abc123；
后续 \d+ 至少要匹配 1 个数字，无字符可用，匹配失败；
回溯机制：.+ 主动让出 1 个字符，匹配 abc12；
剩余 3 交由 \d+ 匹配，整体匹配成功。
 
非贪婪匹配加?，以下：
re.match(r'(.+？)(\d+)', 'abc123')   
’abc‘，‘123’ 
匹配逻辑
.+? 开启非贪婪，从最小数量开始尝试；
先尝试只匹配 1 个字符 a，剩余字符无法满足 \d+ 完整数字匹配，失败；
逐次增加匹配字符：ab → 仍不满足后方数字规则；
匹配到 abc 时，剩余 123 可被 \d+ 完整匹配，匹配成功。
在整个正则表达式的逻辑上，其实就是把加了？的规则匹配优先权放在了最后

base64
写在笔记之前：
二进制文件靠字节来储存数据，这些数据除了有文本数据之外还有逻辑于运算单元，指令单元等，无法直接显示的数据，所以为了让二进制文件可以在记事本这样的文件中显示且不丢数据，需要做如下操作

对二进制文件进行一次再编译，确保其所有字符都可以被表示出来
其实就是把整个文件按每3个一组切分开，每一组用4个可读字符表示存入到另一个文件中
底层原理是：
二进制字节每一个占8bit，3个8bit是24bit
base每6bit查一次表，4个6bit是24bit
base的索引表一共有64个元素，6bit正好每一个数都有代表
注意：
base64的4个可读字符每一个也占一个字节，也就是说文件扩大了33%

扩展：
为什么base索引表里面有64个元素，因为所有的单字节字符一共只有90个，字符表的元素总数必须满足2的阶乘，16，32，64，128
64是最合适的，索引表字符越多文件的扩大比例，编译后的文件/源文件，越小，并且64所代表的6bit和1字节的8bit有最大公约数，所以最合适

base64在切分的时候如果文件的字节不是3的倍数，它会在末尾加上\x00补足，再在编码文件的末尾显示1个或2个=号，表示补了多少字节，解码的时候，会自动去掉

URL在读编码后文件的时候，不能直接读+和/，所以用索引表中-和_来替代+和/

URL、Cookie在显示的时候如果‘=’，会造成歧义，所以不显示等号，在解码的时候补齐就可以了

哈希算法hashlib
哈希算法给相当于每一段文本加上了一个身份证，这里称为消息摘要，摘要和文本一一对应，原文微小的改动，哈希值将完全变化，摘要无法推导出文本信息，给文件加上摘要的方法可以快速找到想要的文件，同时在文件传递的过程中通过计算文件的摘要可以判断文件有没有被篡改。以下：
import hashlib

md5 = hashlib.md5()                     #生成一个哈希值生成器
md5.update(文本.encode(编码方式))  #编码成二进制然后生成它的哈希值
print(md5.hexdigest())    #查看哈希值digest：摘要


哈希值的作用有三个：
第一个是作为唯一标识，用来验证软件的完整性，这种验证必须基于“大众—权威”这种信息传播模型，有一个权威的哈希值做参考；
第二个是当标签用，就像字典的索引快速查找到我们想要的内容；
第三个是利用其无法反推的特性，也叫‘单项不可逆’，做一些简单的加密

用法3：
大型网站的后台通常保存用户的账号和密码哈希值，然后利用用户的账号，计算用户输入的密码哈希值，进行匹配
这样做既保证了网站本身的匹配功能
又可以保证运维人员无法直接查看用户的账号信息从而进行非法操作

注意：彩虹表：一些常用的密码信息摘要的汇总，如123456，258456等的摘要
黑客通过彩虹表可以破解一些常用的密码，为了防止这种现象出现，我们给每个密码加上一些可变长文本生成一个新的密码，然后计算它的摘要，这可以有效的防止彩虹表的入侵，这种给密码加文本的方式被称为加盐，加入的文本被称为盐
用法1：
用户下载一个软件或者文本，想要知道是不是正版，可以直接对比官网的哈希值，
相同是正版，不同的话证明软件或者文本可能被篡改过小心使用

__enter__和__exit__   #上下文管理器的创建方法
给类加上这两个封装方法，就是允许该类实现上下文管理，主要有两个作用：
1.允许在主代码前面和后面加上一些执行内容   
2.允许和with搭配打造一个环境

yield：包含yield的函数是一个迭代器函数，每次只会输出一个内容
with：先执行__enter__，再执行with里的代码，再执行__exit__，收尾的执行相当于给函数创建了一个环境

@contextmanager
通过写一个主调函数调用B函数，在应用层，这个装饰器可以使任意B函数搭配with构建一个环境，并且很方便写入
__enter__和__exit__的内容。以下：

from contextlib import contextmanager
@contextmanager
def create_query(name):
    print('Begin')
    q = Query(name)
    yield q
    print('End')

with create_query('Bob') as q:
    q.query()
yield之前的print('Begin')；q = Query(name)被打包成了__enter__部分，之后的print('End')被打包成了__exit__部分
with先调用__enter__内容，再调用with里面的代码，最后调用__exit__内容
我们可以很方便写入__enter__和__exit__的内容，并且在应用层给Query(name)类打造一个环境


closing
作为函数使用，默认给对象加上上下文管理功能，但无法自定义__enter__和__exit__的内容，以下：

from contextlib import closing
from urllib.request import urlopen

with closing(urlopen('https://www.python.org')) as page
相当于一个简化版的@contextmanager，事实上它就是通过@contextmanager编写的



环境本质：为需要安全执行的代码块，封装必定执行的释放运行内存，或者停止修改环境之外的数据的逻辑，
相当于给装了__enter__和__exit__的类上一个保险，在它因为意料之外的原因停止运行时，停止它对外的修改，并释放它占用的内存，以下：
假如说我们写一个，读取硬盘的程序，如果读取的文件太大，电脑硬盘占满了，没加入环境的话，即使报错了也会持续运行，提前加入环境，收到报错信息他就会立刻停止运行，释放运行资源

venv：构建虚拟的python环境
主要解决两个问题：
1.不同的应用对同一个插件要求的版本不同，创建两个python环境，一个环境允许老应用用老插件一个环境允许新应用用新插件，以下：
A需要Django 2.2，B需要Django 5.0，创建两个虚拟环境，每一个环境对应不同的Django版本
两个环境是完全独立的文件夹，互不干扰。
2.编写的某一个程序需要大量的模块，我们不想在计算机上下载这么多的模块，就在程序文件夹中创建一个虚拟python文件夹，简洁美观高效


实现方式：
下面四种方法是创建python解释器的方法
在系统命令行中输入
python -m venv myenv       #创建一个虚拟环境文件夹，默认保存在命令行所在的路径中，默认不继承系统下载的第三方模块    
python -m venv --system-site-packages myenv      #继承系统下载的第三方模块

python -m venv 你想要的完整路径     #将虚拟环境文件夹保存在指定的路径中
cd 进入目标文件夹
python -m venv myenv     #先进入文件夹，在当前文件夹创建虚拟环境文件夹，效果和上者相同


下面是打开已创建虚拟环境的方法
cd myenv     
cd Scripts    #进入虚拟环境文件夹
.\activate      #将整个命令行改为在venv环境中运行，接下来的操作都会在虚拟环境中运行     #'.'在前‘\’在后
venv文件夹路径 python_file.py     #只运行某一个特定的文件，venv文件夹的路径
注意：如果你是初次运行虚拟环境，计算机运行策略可能并不允许你运行
我们修改运行策略
Set-ExecutionPolicy RemoteSigned -Scope Process         #当前命令行窗口允许进入虚拟环境，临时运行
Set-ExecutionPolicy RemoteSigned -Scope CurrentUser   #当前用户的所有命令行窗口允许进入虚拟环境，长期有效
该命令解释
Set-ExecutionPolicy：表示设置运行策略
RemoteSigned：
1.从网上下载的脚本（包括邮箱附件）必须有可信的数字签名才能运行
2.此电脑上自己写的脚本可以直接运行
-Scope CurrentUser：该策略的作用范围，Process当前命令行窗口，CurrentUser当前用户所有的命令行窗口


下面是退出虚拟环境的方法
（myenv）$deactivate      #在环境中输入deactivate就可以退出环境


删除虚拟环境的方法：
找到venv文件夹直接删除文件夹就可以了，删除时确保命令行没有在虚拟环境中运行



venv的底层原理
1.每次venv一个新的python环境实际上就是创建了一个储存模块的文件夹  旧的解释器+新的储存模块的文件夹
2.临时修改了系统调用python模块和pip下载模块的储存位置的环境变量

再次理解环境比变量：
环境变量和注册表一样都是用来查找文件或程序的标签、索引；这个两个形容都合适，不分先后
环境变量和注册表在开机时都会被加载进入内存，然后回调至硬盘中，但是环境变量在回调之前会保留一份副本在内存中，相当于开了快速通道，所以，以环境变量作为索引的文件，查找效率非常高。下面是一个形象的比喻：
注册表是一本非常厚的书的目录，环境变量是被重点罗列出的章节

requests：一个更强大的链接访问工具
我们不只是从网页上爬取信息还可以对网页数据进行修改和优化
所以本章笔记从两个角度，爬虫和调用api来讲解requests的应用
关于api：
API 让你能绕过图形界面，用代码自动化、批量化地管理自己的数据
并且API是网站管理者发布的，它允许我们以此方法处理部分网站数据
所以看官方提供的api我们只看两个角度，第一是它可以返回什么信息；第二是它允许我们修改哪些网站信息
我们也可以自己捕捉api，Fn+F12------>进行删除或者修改处理-------->找到delete或put对应的url就是api链接


实现方式------------获取链接内容的4种方式，r是返回的链接内容

直接获取
r = requests.get(网站链接)

访问需要密码的网站链接
 r = requests.post( 网站链接,data=包含账号密码和配置文件的字典)
#优点在于不需要对字典数据进行额外的编码

调用api去更新一个内容
r=requests.put(api链接, json=包含更新内容的字典)    以下：
json== {'name': '新名字','email': 'new@example.com','bio': '新的简介'}
#我们的个人信息在服务端可能会打包成对应的链接，身份信息---->身份api；头像信息------>头像api
#我们可以通过代码调用api来操作用户信息；并且当内容和api一一对应的时候，你调用的内容api往往返回的也是一个api

调用api去删除一个内容
r=requests.delete(内容对应的api链接)
#删除后返回的响应内容r，包含一个状态码和空的text

#如果用这四种方法获取、修改、删除网站内容，可以先打开开发者工具，现在网站上手动点击获取、修改、删除操作，工具记录操作方法和操作api，然后利用找到的api用程序模拟获取修改删除操作


5个写入参数的方法--------在访问链接时传入一些数据

GET请求：get请求里的参数是辅助链接更精准的定位和搜索，仍然是链接或者访问的一部分
POST请求：post请求的参数是我们真正发送给网站后台的数据，真正的实现数据传递

对于带参数的链接，可以把参数拆出来单独处理
r = requests.get(网站链接, params=包含参数的字典)   以下：
r = requests.get('https://www.douban.com/search', params={'q': 'python', 'cat': '1001'})
等价于r.requests.get('https://www.douban.com/search?q=python&cat=1001')
这样做可以增强整个链接的可读性、编码速度和对动态参数的处理能力，以下：
1.动态参数的处理：当不同的用户同时访问服务器时，只需要修改字典中的参数，与修改整个链接相比结构更加清晰，后续增加对参数的处理也更方便，可维护性强
2.编码速度：url参数默认不能使用中文、空格和特殊符号，需要将参数编码成百分号形式，如张三 → %E5%BC%A0%E4%B8%89，自己编码很复杂，而params会自动编码，整体编码速度就很快
#可以直接访问网站的某一部分超链接内容

chardet：检测数据的编码方式
使用方式
import chardet
chardet.detect(二进制数据)
返回结果
{'encoding': 编码方式, 'confidence': 可信度, 'language': 语言所属国家}


chardet 与 response.encoding 的区别与使用
chardet：用于自动检测未知数据的真实编码，直接从二进制数据本身分析编码格式，为正确解码提供依据。
response.encoding：仅读取HTTP 响应头中声明的编码，不检测真实数据编码，完全依赖源头提供的编码信息。

编码方式和传输数据的结构体是不一样的，
编码方式控制二进制内容如何展示，JSON、XML、字节数据等结构体则用来梳理数据结构，避免数据原本的含义丢失。
结构体有自己固定的编码解码方法，通常为一种，所以不需要使用chardet检测

只有二进制数据允许检测编码，因为其不可读，且具备多种解码形式
我们检测二进制数据的编码，是为了将其还原为可读的文本。文本已是最终可读形式，因此无法也无需反向检测文本编码。

Thinker：python的绘图模块

python调用Thinker模块---------------------- >编译成c语言------------>TK模块-------------->操作系统的GUI库的api
c、c++、c#------------->GUI库api

Tcp连接通过Socket模块建立，是爬虫requests模块的底层实现方法

Socket模块分为客户端和服务端，我们从这两方面讲解它的实现方法


客户端
import socket

s=socket.socket(socket.AF_INET,socket.SOCK_STREAM)          #创建一个套接字对象
#我们这样理解套接字对象
#我们可以把计算机网络想象成电力系统，把主机想象成一个等待电力交互的房间，套接字对象就像是房间里面的插座，用来传输数据
#socket.AF_INET指定套接字对象使用ip4协议，SOCK_STREAM指定使用面向流的TCP协议

s.connect((ip4地址, 80))                        #connect通常表示这是一个客户端对象，参数第一个是ip地址第二个是端口
#ip地址可以通过URL查找，端口是固定的443
#查找IP地址：在浏览器中找到要查找的网页的URL，在cmd或者powershell中输入：ping URL；nslookup URL
#常见的固定端口：网络服务是443；SMTP服务是25端口；FTP服务是21

s.send(b'GET / HTTP/1.1\r\nHost: www.sina.com.cn\r\nConnection: close\r\n\r\n')                            #向服务器发送请求
#详细解释一下这个请求
#这是三行数据，\r\n回车换行，表示这一行结束；
#GET意思是我要获取信息；/ HTTP/1.1使用的 HTTP 协议版本；
#Host: www.sina.com.cn这表示访问主机的新浪网首页，因为一个服务器 IP 上可能托管了多个网站，Host表示访问主要那一个
#Connection: close告诉服务器这是一次性连接只发送一次数据，不要保持连接，Tcp默认保持连接
#\r\n也是请求头结束的标志，所以我们通常用\r\n\r\n来区分请求头和内容；这表示头的最后一句话和头都结束了

d = s.recv(1024)           #用来获取信息，1024表示单次获取的最大字节数，’recv‘原词receive，接收收到

s.close()                #关闭tcp连接

服务器
s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)     #仍然是创建一个套接字对象
#因为服务器接收的信息量巨大，因此通常需要两个套接字对象，一个负责接收信息一个负责发送信息
#这是第一个，这个套接字对象只接收信息和监听端口，不给用户返回信息

s.bind(('127.0.0.1', 9999))     #绑定端口，两个参数一个是服务器的网关一个是服务器的端口号
#服务器的端口必须足够的固定和透明公开，以保证所有用户都可以正常访问，因此我们必须手动设置
#1-1024号端口都有协议规定所以必须使用管理员权限才可以监听

s.listen(5)            #开始监听端口，参数表示这个端口最多排队排5个链接

while True:
    sock, addr = s.accept()           #这里返回两个对象，一个是新的sock对象一个是客户端的地址addr
    t = threading.Thread(target=tcplink, args=(sock, addr))         #target是线程运行的目标函数，args是目标函数需要的参数，带入目标函数中
    t.start()                                    #这里我们通过建立一个新线程来向客户端发送信息


这里解释一下为什么客户端连接计算机需要多个端口，而服务器连接多个连接却可以一个端口搞定
因为协议就是这样规定的，为了区分不同的Tcp连接，避免消息发送串台，客户端和服务器必须有一个妥协，以下：
Tcp链接通过四元组来区分每一条链接：(客户端IP, 客户端端口, 服务器IP, 服务器端口)
当同一个客户端和同一个服务器建立2个及以上链接的时候，客户端ip和服务端ip是固定的，要区分这两条链接只有三种情况：
客户端端口相同，服务器端口不同
客户端端口不同，服务器端口相同
客户端和服务器端口都不同
考虑到服务器本来就要接收很多Tcp连接，承受极大的并发压力，所以我们把建立新端口的任务转嫁到客户端上，客户端建立两个不同的端口来区分Tcp链接，而服务器只需要借助区分好的链接发送不同的信息就可以了

tcp协议把区分tcp的复杂性转嫁给客户，这种多端口对一端口的网络服务模式，就是现代网络系统可以处理高并发的基石
