数据类型
python在定义数据时可以声明数据类型，这在fastapi中有很重要的作用

定义类型只需要在变量后方加上冒号和类型名称即可，以下：
def main(name：str)     #表示这个类型只能是字符串

定义类型的关键点在于类型的种类和类型的定义方式
特殊的定义方式：泛型和多类型union
泛型
在容器作为被定义的类型时，容器内部的元素可以继续声明类型，这种容器套类型的形式叫做泛型，以下：
def main(name：list[])    #定义容器做类型  
def main(name：list[str]) #定义容器并且规定容器内数据只能是str，就是定义泛型
def main(name：list[int,int，str])  #这表示容器内有三个元素，分别是整数，整数，字符串的形式

多类型
一个变量可以为多类型中的任意一种，我们用多类型定义它，以下：
def main(name：str，score：int|float)    #int|float表示score既可以是整数类型又可以是小数类型
def main(name：str，score：int|float，a：list[]|tuple[])  #a既可以是列表又可以是元组
类型中间加竖杠表示变量可以属于多个类型中的一种


Pydantic:一个对数据进行过滤的模块
过滤操作重要的点有两个：滤网和过滤方法
滤网：把想要的数据定义在一个目标类中，并给数据附上类型
过滤的方法：将原始数据做参数传入目标类生成一个实例
过滤操作：
把想要提取的数据定义成一个目标类，用目标类去过滤原始数据得到干净的目标数据，以下：
class User(BaseModel):                #把想要是数据定义在目标类中并附上数据类型，相当于定义了一个滤网
    id: int
    name: str = "John Doe"
    signup_ts: datetime | None = None
    friends: list[int] = []

external_data = {                           #原始数据
    "id": "123",
    "signup_ts": "2017-06-01 12:22",
    "friends": [1, "2", b"3"],
}

user = User(**external_data)        #把数据通过滤网生成一个类的实例,这算是完成了过滤
#该实例过滤掉了所有我们不需要的元素，并且在过滤过程中改写一些数据的类型，如:‘30’--->30;使这些数据更符合我们的需求

路由：又叫路径，是浏览器访问网页的地址，定义在装饰器中，与处理函数成对出现



路由分为静态路由和动态路由
静态路由’/files/name‘：常见的访问网站的地址；动态路由’/files/{name}‘：路由不固定，name位置的参数可以传递给后端

路由顺序：
1.一个路由只能对应一个处理函数，以下：
@app.get("/users")                      @app.get("/users")
async def one():                            async def two():
#访问"/users"时，只会运行第一个处理函数，第二个处理函数def two()无法被启动
2.动态路由必须位于静态路由之下，如果相反，静态路由将无法被匹配到。以下：
@app.get("/users/{user_id}")
async def one(user_id: str):

@app.get("/users/me")
async def two():
#访问"/users/me"时，路由从上到下匹配，匹配到"/users/{user_id}"满足条件将不会再往下匹配,最终只会出发def one(),def two()被def one()覆盖掉了
#反之，访问"/users/me"时，先two后one没有任何问题



预设动态路由值
预设值需要两步：将预设值装入容器中+对路由值校验，非预设值无法传入
标准做法：常用容器list、tuple、dict+if判断
更优雅省时的做法：定义一个枚举类容器，并在传输处理函数时声明参数类型，以下：
class ModelName(str, Enum):    #Enum使类变成一个枚举容器，并给容器中的每一个元素设置新的数据类型ModelName
    alexnet = "alexnet"                 #str限制类中定义的元素只能是字符串类型
    resnet = "resnet"
    lenet = "lenet"           

@app.get("/models/{model_name}")
async def get_model(model_name: ModelName):   
#只允许ModelName类型的数据输入，而ModelName类型的数据只有三个，就相当于预设了这3个数据



动态路由传路径参数的方法
因为路径和路由都是由‘/’连接而成，所以只用‘/{}’无法捕捉路径，以下：
访问路径
/files/code_FastAPI\awesome-project\main.py    #无法知晓哪一个是需要捕捉的路径

引入捕获路径参数并传入后端的方法，在@app.get()中设置 "/files/{file_path:path}"，以下：
/files\\code_FastAPI\awesome-project\main.py   #通过双斜杠可以很轻松的判断出传入后端的参数 code_FastAPI\awesome-project\main.py

以下是完整实例：
后端实设置
@app.get("/files/{file_path:path}")     #采用file_path:path
async def read_file(file_path: str):
    return {"file_path": file_path} 

浏览器访问
/files\\code_FastAPI\awesome-project\main.py 

网页返回值
"file_path": code_FastAPI\awesome-project\main.py

查询参数：没有在路由路径中预先占位，而是以?key=value&...形式附加在URL末尾的可选参数。以下：
@app.get(("/items/")     #定义时路由中未定义查询参数
http://127.0.0.1:8000/items/?skip=0&limit=10    #查询时加载路由？后，以&连接


查询参数：类型声明和默认值的设置

声明类型
和路由参数定义一样，查询参数也可以声明类型，包括多类型。以下：
@app.get("/items/{item_id}")
async def read_item(item_id: str, q: int | None = None，skip:bool=false):       #给可选参数q设置int或者None类型

类型转换：字符串str和数字int可以在输入时相互转换。以下：
http://127.0.0.1:8000/items/？q=12       #路径参数默认是str形式，函数参数只接受int形式，会在框架中做默认转换
http://127.0.0.1:8000/items/?skip=20    #任何数值的数据除0外，都会被转换为bool值true


设置默认值
就像路径参数定义时一样，查询参数定义时也可以设置默认值，以下：
@app.get("/items/")
async def read_item(skip: int = 0, limit: int = 10):   #设置默认值后，即使在访问时未输入查询参数，函数也会以参数函数的默认值允许

必选查询参数
没有设置默认值的参数称为必选参数，访问时必须传入路由，否则会报错，以下：         #传入路由的方式可以参照本节首段
@app.get("/items/")
async def read_item(skip: int, limit: int):                 #在访问/items必须传入skip和limit，否则函数无法运行

请求参数----用来处理和获取请求体数据

获取数据，从请求体中
定义Basemodel子类，并在处理函数中声明该类，对应的参数会自动捕捉请求体中的同名数据，以下：
class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None          #定义Basemodel子类

@app.post("/items/")
async def create_item(item: Item):    #在函数中声明它，参数item会自动捕获请求体中的同名数据
注意：和路由参数与查询参数类似，请求体参数也可以声明类型，设置必选参数，设置默认参数，不过都是在BaseModel子类中设置


使用数据
和类调用属性相同，通过类.方法(),来使用捕获的数据
@app.post("/items/")
async def create_item(item: Item)：
         item.name=name的值
         item.description=description的值
         item.price=price的值
         item.tax=tax的值
注意：同样是创建类，使用枚举，可以严格限制参数的可选范围，将其锁定在预先定义好的几个合法值中；使用Basemodel子类，则是可以使参数直接从前端捕获数据。这有重大区别，并且枚举类可以作为Basemodel子类的属性类型声明，限制子类属性的取值范围，以下：
class enum(Enum):
    str1 = "a"                 
    str2 = "b"
    str3 = "c"    

class Item(BaseModel):
    name: enum
#name的值被限制在了’a‘’b‘’c‘之间


最后总结：
根据不同位置（URL 里、问号后、Body 里）传来的数据，我们在函数里定义参数的方式也不一样：
1.从路由中获取数据-----路由参数
定义时与路由中的{可变路径}同名，def def create_item(item_id:int)；@app.get("/items/{item_id}")
可以从路由中捕获数据，用在参数中接收

2.从请求体中获取数据-----请求体参数
定义时参数声明BaseModel 子类，async def create_item(item: Item)；class Item(BaseModel):
可以从请求体中捕获数据，并用参数接收

3.从路由？后面获取数据------查询参数
定义时声明了参数类型，但是既没有继承BaseModel子类，又没有与路由中的‘{可变路径}’同名，那么这个参数就是查询参数
可以从路由的？后面捕获数据，并用参数接收

查询参数的校验：
对查询参数进行筛选，只留下符合条件的参数
#注意：本章的筛选主要是针对字符串进行的筛选


实现方式
方法：
Annotated(数据类型，元数据，元数据.......)   #Annotated的参数是元数据
#元数据：一组筛选条件组成的集合
Query(筛选条件)   #Query的参数的筛选条件

实现代码
Annotated紧跟冒号放置，需要传入两个参数，数据类型和元数据，查询参数对应的元数据是Query
async def read_items(
    q: Annotated[str | None, Query(min_length=3, max_length=50)] = None         #这个筛选表示字符串的长度必须是3-50之间
):
#Annotated和Query的组合只是加入了校验规则，这并不影响数据类型和默认值的声明规则

Query可选参数
1.正则表达式---pattern
q: Annotated[str | None, Query(min_length=3, pattern=‘正则表达式’)] 
#这个并不是完全体的正则表达式，只支持字符串不支持数字、列表

#Query通常情况下是筛选条件，但是也包括一些功能性参数
2.接口美化参数----重命名title和注释description
q: Annotated[str | None, Query(min_length=3, title="新名称"，description="这是对参数的注释")] 
#在文本文档redoc可以看到参数的新名称，在交互文档docs中可以看到对参数的注释

3.别名参数----alias
q: Annotated[str | None, Query(min_length=3, alias="一些超规的命名方式")]
#Python 变量命名存在语法限制，不能带横杠、特殊符号、中文等
#alise相当于给函数起了个小名，用字符串来代替函数的命名，可以拓展前端url或者请求体的参数写法



列表类型
#所有容器类型的请求参数，默认从请求体中捕获数据，但是搭配 Query() 强制从 URL 查询参数解析数组
q: Annotated[list[str], Query()] = ["foo", "bar"]
#这表示这是一个查询参数，默认值是["foo", "bar"]，Query做元数据就代表这个参数一定是查询参数



更复杂的校验方式
当常规的AQ无法完成筛选时，需要定义一个筛选函数，使用pydantic.AfterValidator后置校验
步骤概述：
导入 AfterValidator------>定义纯校验函数------->将校验函数传入 AfterValidator，作为 Annotated 的元数据,以下：

from fastapi import FastAPI
from typing import Annotated
from pydantic import AfterValidator

app = FastAPI()

def check_valid_id(id_str: str) -> str:                 # 1. 自定义校验函数
    if not id_str.startswith(("isbn-", "imdb-")):       # 自定义业务规则：ID必须以 isbn- / imdb- 开头
        raise ValueError('ID格式错误，必须以 isbn- 或 imdb- 开头')
    return id_str

@app.get("/items/")
async def read_items(
    item_id: Annotated[str | None, AfterValidator(check_valid_id)] = None     # 组合校验：字符串 + 自定义后置筛选，可选参数
):
    return {"item_id": item_id}
#AfterValidator做元数据可以完成更加复杂的筛选

路由参数的校验：
对路由参数进行筛选，留下符合条件的参数


实现方式
方法：Annotated，Path
#实际上Path是一个函数，每次运行返回一个Path实例
将Path作为元数据传入Annotated，并将筛选条件传入Path，一下：
item_id: Annotated[int, Path(title="The ID of the item to get")]


参数排序
如果一个python函数需要传入多个参数，那么无默认值的参数必须在前面，这是py的参数排序规则
#ps:路由参数无法设置默认值
强制的排序有时候并不优美，因为通常情况下，重要的参数应该排在前面
解决这个问题的方法有两个：
1.使用Annotated给每一个可以声明默认值的参数声明默认值
#当大部分参数都有默认值后，参数的排序在规则下将会非常顺畅
#事实上，fastapi中大部分时候都是使用这个排序方法
2.使用*号，使参数变为关键词参数，以下：
read_items(*, item_id: int = Path(title="The ID of the item to get")：
#关键词参数采用一对一的识别模式，所以不会受到默认传参方式的任何影响
#这在前端传参的时候必须使用，‘item_id=xxx’形式传参，会限制前端的传参方式
#通常情况下，使用了Annotated的参数往往不需要使用*


数值校验：
可以传入Path或者Query等元数据的筛选条件
gt=1：必须大于1
ge=1：必须大于等于1

lt=10：必须小于10
le=10：必须小于等于10
#大于和小于一般成对出现，以下：
size: Annotated[float, Query(gt=0, lt=10.5)
#size的值必须大于0，并且小于10.5
length:Annotated[float, Query(ge=0, lw=10.5)
length的值必须大于等于0，小于等于10.5

查询参数的模型
参数模型：
用BaseModel子类设计的参数模板

实现方式
设计一个参数模板，然后在参数中用Annotated和Query声明它，以下：
class FilterParams(BaseModel):
          limit: int = Field(100, gt=0, le=100)
          offset: int = Field(0, ge=0)                      #设计一个模板

def read_items(filter_query: Annotated[FilterParams, Query()]):  #在函数中声明它

模板中的常用的方法
Field：对参数做筛选
#对想要筛选的参数使用
#单个参数，在元数据Query中增加筛选条件，参数模板需要在Field()中增加筛选条件

literal：literal：限制变量的值只能是指定的几个字面量之一
#在实际应用中，和Enum作用有所重叠


BaseModel子类和Enum的子类的区别
Enum是限制的固定的几个值，而BaseModel限制的是参数和类型约束
在实际应用中
BaseModel就像一个具有完整表头的模板，Enum像是它的一列或者一列中的一部分具体内容
#Enum可以跨类型设置固定值，但我们通常不这么做


禁止命令
对整个类使用，设置边界的严格性
默认---无命令：允许额外的参数输入，但只会保留模板参数
model_config = {"extra": "forbid"}：不允许额外的参数输入，一旦检测到非模板参数就会报错
model_config = {"extra": "allow"}：允许任何参数输入，并且会保留任何参数
#强边界设置可以及时提醒开发者，防止发生更大的错误，以保证数据和资产安全，以下：
#前端测试时用户账号密码不严格输入会立刻报错，在开发阶段发现错误，就可以避免应用上线后造成更大的损失
#弱边界给与用户更高的自由度，同时方便后续的调试和维护

#强边界和弱边界以后多注意实例

介绍多个多个请求体参数的数据的嵌套结构

请求体参数
声明BaseModel子类类型的参数，默认是请求体参数，以下：
class User(BaseModel):
async def update_item(user:User|None=None):
#user默认是请求体参数

对于单个参数来说，写一个类来表示请求体参数显然很复杂，所以用常用Annotated和Body强制声明请求体参数，以下：
async def update_item(item2:Annotated[str,Body(embed=True)]):
#item2也是请求体参数



多个请求体参数的数据结构
请求体数据在前后端传输时是json形式，多个请求体数据的json结构是大字典里套小字典
多请求体数据：一个路径操作函数中声明了很多个请求体参数，所有的请求体参数的数据合起来就叫多请求体数据

响应模型----返回值需要经过该模型筛选
响应模型：做一张滤网，过滤掉哪些不应该被输出的数据，并限制输出数据的类型，
第一种传入响应模型的方法是创立返回值类型注解，以下：
class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None
    tags: list[str] = []

@app.post('/items/')
async def create_item(item:Item)->Item:       #这里创建类型注解
    return item
# ->Item必须和return的返回值类型相同
#Item在输出时会经过BaseModel子类的过滤


另一种传入响应模型的做法，路由参数response_model
@app.post('/items/'，response_model=Item)    #这里设置输入响应参数
async def create_item(item:Item)->Any:       
    return item
#’response_model=Item‘设置完成后会直接传入fastapi框架，作为结果筛选和类型限制的参数
#事实上，类型注解’->Any‘的底层也是fastapi框架翻译成’response_model=Item‘来实现的
#像上诉代码中那样，如果类型注解和响应参数同时存在，框架只会采取响应参数中的模型
此时的类型注解更像是程序内部的注释，对外展示和实际采用的模型都是response_model模型



一个特殊的类型注解-----reponse
reponse作为类型注解使用，允许我们不通过框架从零开始自定义响应对象，以下：
from fastapi import Response
async def get_portal(teleport: bool = False) -> Response:
    if teleport:
        return RedirectResponse(url="https://www.youtube.com/watch?v=dQw4w9WgXcQ")
    return JSONResponse(content={"message": "Here's your interdimensional portal."})
#另外，如果只是想把类型注解当做注释使用，在路由中输入响应参数response_model=None，以下：
@app.get("/portal", response_model=None)
#此时类型注解将不会被fastapi翻译，而只是作为一个注释使用

常见的模型结构：主模型(数据源模型)和输出模型
在实际工程开发中，经常会出现一个模型包含另一个模型全部或部分字段的情况，以下：
class BaseModelUser(BaseModel):   #这是数据源模型
     username:str
     password:str
     email:EmailStr
     full_name:str|None=None

class UserOut(BaseModel):      #这是输出模型
     username:str
     email:EmailStr
     full_name:str|None=None

#这样做的作用主要有两个
1.实现内部逻辑与外部接口区分-----避免客户端收到额外字段
数据源模型可能会随着业务发展不断增加字段，例如：
class UserModel(BaseModel):
    username: str
    password: str
    email: EmailStr
    full_name: str | None = None
    create_time: datetime             #这是增加的字段
如果接口直接返回数据源模型，客户端可能会收到额外字段。
而使用 UserOut 后：
@app.get("/users/{id}", response_model=UserOut)
无论内部模型如何变化，接口返回结构都保持稳定，这样可以避免内部修改影响外部调用者。
2.保护隐私
密码、密匙、加密的盐等不能直接返回给用户，所以如果一个pydantic模型包含这些信息，就需要把这些信息拿掉再定义一个模型------数据源模型和输出模型，以防数据的泄露

响应状态码的设置和类型
手动设置响应成功的状态码，以下：
from fastapi import FastAPI
app = FastAPI()
@app.post("/items/", status_code=201)
async def create_item(name: str):
    return {"name": name}
#响应成功将返回201响应码
#状态码是程序响应的第一语言，一个合格的状态码可以省去很多团队交流的时间



常见的状态码代表的意义
100 - 199 服务器已收到请求，但是还未发送响应
200 - 299 表示响应“成功”
300 - 399 表示收到了响应跳转给其它的网页
400 - 499 用于表示代码写错了或者服务器崩了，要去服务器看报错信息

编辑器自动补全
下载pylance和python扩展后，我们不需要记住每一个响应码代表的意义，只需要打出status.cre,编辑器会自动补全，以下：
status_code=status.

async def update_item(item_id: str, item: Item) -> Item:      #item_id用来提取初始字段，item模型包含的只是需要修改的字段
    stored_item_data = items[item_id]
    stored_item_model = Item(**stored_item_data)                #创建初始数据模型-----主体模型，用从字典拿出来的初始数据创建模型
    update_data = item.model_dump(exclude_unset=True)    #取出模型中的数据--------使用户传入的pydantic模型变为字典形式
    updated_item = stored_item_model.model_copy(update=update_data)     #做合并，用打散出的字典字段覆盖掉初始数据模型的对应字段，生成最终模型
    items[item_id] = jsonable_encoder(updated_item)            #将最终模型转变为json格式，赋值给原字典
    return updated_item

#.model_dump(exclude_unset=True)：Pydantic 模型转字典，并排除掉pydantic模型的默认值
#.model_copy(update=update_data)：用传入的字段update_data覆盖掉初始模型对应的字段，生成新的模型

带有yield的依赖项
用depend调用带有yield的依赖项可以实现数据库连接的创建和自动销毁，因此需要创建连接和自动销毁的场景都需要用到yield依赖项
yield依赖项使用场景：数据库、外部 API、文件系统等所有需要用到上下文管理的地方
实现方式
async def get_db():
    db = DBSession()
    try:
        yield db                     #分隔函数，是函数分两步完成
    finally:
        db.close()
#自动销毁原理：在fastapi中，当一个依赖项使用yield的时候，这个依赖项就被增加了上下文环境，用depend调用依赖项时，会自动进入这个上下文环境，并且这个环境会自动识别操作函数的结束标志
#关于yield：
#对于迭代器函数，yield可以使迭代器进入运行状态；对于正常的函数，yield可以把一个函数分成两次运行
#这意味着可以在一个函数/依赖项中实现连接的创建和销毁操作，也就是需要帮我们调用两次，depends实现了第一次手动调用，上下文环境实现了第二次调用



try....yield...except组合也可以用来捕获错误
通常我们不这样做，我们有更好的方法抛出错误，直接使用raise，并且可以定义错误处理器，但是try....yield...except确实是一个方法
def get_username():
    try:
        yield "Rick"
    except InternalError:
        print(“这里有一个错误")
        raise
#except一定要加上raise，一定要把错误抛出去，吞掉错误比抛出错误更可怕
#错误会逐层抛出，调用函数的错误和子依赖项的错误都会被抛出去，但是调用函数启动的后台进程的错误不会被抛出



控制依赖项的关闭的时机
Depends(get_username, scope="function")
通过scope=function/request来决定我们是在响应前前还是响应后关闭依赖项，进而决定是一次性输出内容还是分批次输出内容
function：在return前关闭依赖项，一次性传输所有内容，对内存的上限要求更高，但是可以使数据库应对高并发场景
request：在return后关闭依赖项，分批次传输所有内容对数据库要求更高，要求数据库可以释放更多的连接，但是对内存的要求很低
如不主动声明，默认 scope="function"，分批次传输

哈希加密密码，以及jwt加密令牌

所谓的安全性总结起来就一句话：
保存用哈希密码保存，验证时验证哈希密码
令牌用jwt(包含内容，时间间隔的字典，密匙，编码方式)加密，接收时用jwt(加密的令牌，密匙，编码方式)解密
取值信息经过两道验证才能发送到后端操作函数中，这两个合在一起构成了安全性验证

整个安全性代码分成两部分：
第一部分安全校验并发送令牌；第二部分实现接受令牌并返回数据，数据库中提取的数据

jwt加密令牌主要发生在第一部分，验证哈希密码也发生在第一部分，可以说这两部分构成了安全校验的全部内容


哈希密码：我们在数据库中存密码时，存哈希密码而不是普通密码

def authenticate_user(fake_db, username: str, password: str):
    user = get_user(fake_db, username)
    if not user:
        verify_password(password, DUMMY_HASH)     
        #这里是无效验证，卡一下时间，用来保证无论账号还是密码错误，函数运行时间都一致，以防‘时间攻击’ 
        #时间攻击：通过函数运行时间来推测账号是否存在，进而攻击指定账号
        return False
    if not verify_password(password, user.hashed_password):
        return False
    return user                      #返回一个用户信息

def create_access_token(data: dict, expires_delta: timedelta | None = None):     #令牌内容和有效时间
    to_encode = data.copy() 
    if expires_delta:
        expire = datetime.now(timezone.utc) + expires_delta
    else:
        expire = datetime.now(timezone.utc) + timedelta(minutes=15)
    to_encode.update({"exp": expire})                                                                      #将间隔和内容添加到一起
    encoded_jwt = jwt.encode(to_encode, SECRET_KEY, algorithm=ALGORITHM)   #生成加密令牌
    return encoded_jwt

@app.post("/token")
async def login_for_access_token(

) -> Token:

    if not user:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Incorrect username or password",

        data={"sub": user.username}, expires_delta=access_token_expires
    )                                                                                                                                           《标记》
    return Token(access_token=access_token, token_type="bearer")                                     《标记》

def read_heroes(
    session: SessionDep,
    offset: int = 0,
    limit: Annotated[int, Query(le=100)] = 100,
):
    heroes = session.exec(select(Hero).offset(offset).limit(limit)).all()
    #重点是这行代码，elect：选择；offset：偏移；limit：限制
    #elect(Hero)	构建一个查询，表示"我要查询 Hero 这张表/这个模型"              确定表   
    #offset(offset)	跳过前 N 条记录，从N+1条开始取值（N = 变量 offset 的值）  确定查询起点
    #limit(limit)	        只取 M 条记录（M = 变量 limit 的值）                                       确定查询数量
    return heroes

中间件
中间件：是一个独立函数，位于请求和操作函数中间
#中间件可以在请求到达操作函数和响应输出操作函数之前对请求/响应，进行额外的一步操作


创建方式有两种：装饰器创建中间件函数；用类包裹中间件函数，使用中间件方法启动
装饰器创建中间件函数
@app.middleware("http")
async def middle_fun(request: Request, 操作函数):
#中间件函数包括两个参数：request：请求信息；call_next:操作函数
#可以在操作函数之前或者之后对请求信息进行修改
#注意：大多数操作函数都是异步函数，所以在使用时要加上await，以下：
response = await call_next(request)

类包裹中间件函数，使用方法启动
class AuthMiddleware(BaseHTTPMiddleware):
         async def middle_fun(self, request: Request, 操作函数):

app.add_middleware(DebugMiddleware)
#仍然是两个参数，请求信息和操作函数；仍然可以在操作函数前后对请求信息进行修改
#类可以创建一个操作函数独有的作用域，为操作函数配置复杂的变量和方法，可以很好的应对大型的中间件函数对参数的需求



中间件的洋葱结构----多重嵌套
中间件也可以被其它的中间件嵌套，也就是说cal_next不仅可以是操作函数，还可以是中间件函数
在多重嵌套的中间件结构中，请求从外到里进入操作函数，响应从里到外输出操作函数：
请求----->中间4---->...........操作函数------>中间1----->.....---->中间4---->响应
#就像俄罗斯套娃一样，传值从外到里，取值从里到外，以下:
@app.middleware("http")
async def funA(request: Request,操作函数):

@app.middleware("http")
async def funB(request: Request,funA):
请求--->funB---->funA----->操作函数----->funA------>funB------>响应

跨源通信----模拟真实的前端访问后端api
前端 源 的概念，源是浏览器自动分配的
源：一个服务器地址，由协议+域+端口构成，这个地址包含了很多文件，文件之间可以自由通信---前端可以调用后端api，后端可以接受 前端的消息
#源包含一个主文件，输入地址默认直接打开主文件，也可以通过  源/文件名  打开其它文件
#常见的协议：http，https；域：myapp.com，localhost，localhost.tiangolo.com；端口：80、443、8080



前端和后端天然不同源，因为它们运行在不同的环境中（浏览器 vs 服务器），端口必然不同，所以前端调用后端api必须实现跨域操作
中间件CORSMiddleware可以实现跨域协作
#其实就是后端设置白名单，允许前端调用------即使加入白名单，前端也无法访问被jwt加密的方法
实现方法
导入中间件
from fastapi.middleware.cors import CORSMiddleware
创建白名单
origins = [
    "http://localhost.tiangolo.com",
    "https://localhost.tiangolo.com",
    "http://localhost",
    "http://localhost:8080",
]
启用中间件
app.add_middleware(
    CORSMiddleware,
    allow_origins=origins,         #启用白名单
    allow_credentials=True,     #允许cookie传入后端
    allow_methods=["*"],          #允许访问所有方法
    allow_headers=["*"],           #允许所有请求头传入后端
)
